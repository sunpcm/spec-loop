# 飞书自建应用配置

本文覆盖 Demo 第一轮飞书最小配置、结构化需求入口命令和受控确认合并入口。阶段 1～4 的飞书认证、通知、长连接与 `状态` 已完成真实验收。受控确认合并入口启用需合并本 PR 并重启控制器；启用后，每个业务需求依次完成文档 PR 和代码 PR 合并。受控合并契约见 [飞书受控确认合并 PR](feishu-merge-plan.md)。应用由用户自行在飞书开放平台创建和配置，secret 只写入本地 `.env.local`，不要粘贴到聊天、Issue 或 PR。

## 1. 创建自建应用

1. 打开 [飞书开放平台](https://open.feishu.cn/)，进入「开发者后台」。
2. 创建「企业自建应用」，记录 `App ID` 和 `App Secret`。
3. 在「应用能力 → 添加应用能力」中启用「机器人」。

## 2. 最短权限

在「权限管理」中只开通以下权限：

| 权限 | 用途 |
| --- | --- |
| `im:message` | 机器人读取群消息事件、发送文本消息 |

第一轮不需要通讯录、日历、云文档或其他业务权限。后续扩展时再按实际功能单独追加。

## 3. 事件订阅

1. 进入「事件与回调 → 事件配置」。
2. 订阅方式选择「使用长连接接收事件」（Demo 使用官方 Node SDK 的长连接，不暴露公网回调地址）。
3. 添加事件：`im.message.receive_v1`（接收消息）。
4. 在「应用发布」中创建版本并发布；未发布的应用版本无法在正式群里收到事件。

### 复用现有应用的限制

同一自建应用的多个独立长连接客户端由飞书随机分流事件，不能同时在线运行 OpenClaw 与本 Demo：一方收到消息时另一方收不到。若现有 OpenClaw 服务必须继续在线，请为本 Demo 单独创建一个应用；若改为本 Demo 独占该应用，请先确认 OpenClaw 已停用。

## 4. 绑定会话与白名单

1. 把机器人加入用于 Demo 的群聊，或打开机器人的一对一单聊。首版只能绑定一个会话。
2. 获取会话 `chat_id`（通常以 `oc_` 开头）：群聊可在开发者后台「开发者工具 → API 调试台」调用 `im.chat.list`，或从事件调试日志的 `message.chat_id` 读取；单聊以实际事件字段为准。
3. 获取允许发命令成员的 `open_id`（通常以 `ou_` 开头）：可通过 `im.chat.members.list` 调试，或从 `im.message.receive_v1` 事件日志的 `sender.sender_id.open_id` 读取。
4. 将机器人加入群后，在群里发一条消息确认事件日志能看到该消息。

白名单为空时模块会拒绝所有命令（默认拒绝），但阶段通知仍会发送到 `FEISHU_CHAT_ID`。

命令只在 `FEISHU_CHAT_ID` 指定的这一个会话内生效：即使机器人在其他群，或白名单用户在其他会话发消息，都不会执行命令。

## 5. 本地配置

```bash
cp .env.example .env.local
```

然后编辑 `.env.local`：

```dotenv
FEISHU_ENABLED=true
FEISHU_APP_ID=cli_xxx
FEISHU_APP_SECRET=你的AppSecret
FEISHU_CHAT_ID=oc_xxx
FEISHU_ALLOWED_USER_IDS=ou_user1,ou_user2
```

`.env.local` 已被 `.gitignore` 排除；如果本地尚未排除，请先补充忽略规则再填写 secret。

## 6. 支持的命令

入口启用后支持以下命令：

| 命令 | 行为 |
| --- | --- |
| `需求：描述` | 提交结构化需求；进入全局串行队列 |
| `/require 描述` | 与 `需求：描述` 等同，兼容 ASCII 冒号 |
| `/status` | 返回当前 Demo 状态 |
| `状态` | 直接返回本地状态快照中的 12 位 hex 请求 ID、当前阶段、文档 PR/代码 PR，或脱敏错误摘要 |
| `重试需求 <请求ID>` | 只恢复对应需求请求的未完成阶段 |
| `/retry <Issue编号>` | 对指定 Issue 重试当前失败阶段 |
| `重试 #<Issue编号>` | 等同 `/retry <Issue编号>` |
| `合并 PR #N`、`/merge N` | 对受管 PR 做预检并返回 10 分钟确认码，不写远端 |
| `确认合并 #N <确认码>` | 重新校验后执行受控同步 Merge |
| `帮助`、`/help` | 返回中文命令说明和两次人工 Merge 流程 |

### 6.1 需求命令规则

仅支持文本消息，且必须带 `需求：`、`需求:`、`/require ` 前缀。描述保留内部换行，规范化首尾空白后必须为 1～2000 字符。示例：

```text
需求：在计数器页面增加“翻倍”按钮，点击后把当前值乘以 2。
```

```text
/require 在计数器页面增加“翻倍”按钮，点击后把当前值乘以 2。
```

- 非文本消息不进入需求处理，首版不承诺自动回复。
- 空描述、只有空白或超过 2000 字符时返回中文错误，不调用 Pi。
- 请求 ID 为 12 位小写十六进制，例如 `a1b2c3d4e5f6`。
- 首版只更新 `docs/specs/counter.md` 中现有 `REQ-CNT-01`；不新增或删除需求块，也不写 `src/**`、其他文档或仓库。
- 控制器按业务需求创建带 `spec-patch` 标签的 docs-only PR。用户人工 Merge 该文档 PR 后，自动触发既有编码流程；生成的代码 PR 仍需用户人工 Merge。
- 同一飞书 `messageId` 的重复投递按持久记录去重；相同描述复用当前请求，其他描述在已有未结束请求/PR 时只会得到现有请求链接。
- 当前 `main` 与请求 `baseSHA` 不一致、远端状态读取失败或 PR 状态不明时 fail closed，不继续创建或重试旧文档。

### 6.2 未知消息与帮助

`帮助`、`/help` 返回中文说明，明确“先合并文档 PR，再合并代码 PR”。文档另行提醒：已合并不等于部署完成。未知文本也返回该帮助，不进入需求生成、普通闲聊或多轮编辑。该反馈仍受绑定会话和操作者白名单限制，不可通过其他会话绕过。

### 6.3 手机操作示例

手机飞书适合提交需求、发送 `状态`、预检/确认受管 PR 和打开 GitHub 通知链接。用户可在 GitHub 手机网页或桌面端审查，受控合并入口启用后按 [飞书受控确认合并 PR](feishu-merge-plan.md) 在飞书完成确认：

```text
需求：在计数器页面增加“翻倍”按钮，点击后把当前值乘以 2。
```

收到请求 ID 后查询：

```text
状态
```

若通知显示阶段失败：

```text
重试需求 a1b2c3d4e5f6
```

`重试需求` 只操作该 spec 请求，不会重跑 `重试 #N` 对应代码 Issue。通知或本地持久化失败时先发送 `状态` 重新取得现有 PR 链接；不要因重复发送需求而新建第二个 PR。

## 7. 去重、串行与恢复

- 全局只运行一个 Pi 作业；需求、Planner、Worker 与轮询共用一个串行队列。
- 同一 `counter.md` 目标只允许一个未结束需求或 PR；已有活动 Worker/代码 PR 时，新需求被拒绝并返回当前交付信息。
- `messageId`、请求 ID、阶段、`baseSHA`、分支、commit、PR、错误和时间持久保存；进程重启不得再次调用 Pi 或重复创建 PR。
- 外部操作前先保存阶段。push、PR、标签或飞书通知失败后，用 `重试需求 <请求ID>` 恢复；已生成的有效产物保留并先做远端对账。
- 飞书发送失败不回滚已创建的 GitHub 对象；状态与错误消息不包含 secret、完整模型 stdout 或原始命令输出。
