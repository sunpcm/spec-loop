# 本机只读流程面板

本机面板用于观察需求请求、代码交付和流程证据，不提供业务重试、合并、部署或任意文件访问入口。真实模式按后端 DTO 动态绘制流程；演示模式用一组浏览器内合成时间线说明从需求文档到部署回执的完整闭环。产品行为仍以已进入 `main` 的 `docs/specs/*.md` 为准，面板展示不能替代 GitHub、固定检查、部署与人工验收记录。

## 启动

使用 Node 24，在仓库根目录执行：

```bash
npm ci
npm run panel
```

`npm run panel` 先运行 `build:panel` 生成独立的 `.orchestrator/panel-dist/`，再启动只监听 `127.0.0.1` 的 Node 服务。默认访问地址为 <http://127.0.0.1:4001>。原有计数器前端开发页和构建产物不受影响。

面板服务从显式状态路径读取快照，默认路径为当前目录下的 `.orchestrator-state.json`。可通过 CLI 指定状态文件、面板端口和控制器健康检查端口：

```bash
node orchestrator/panel.ts \
  --state /absolute/path/to/.orchestrator-state.json \
  --port 4001 \
  --control-port 4000
```

参数由面板服务严格校验，不允许监听非本机地址。面板只接受 `GET`/`HEAD`，拒绝跨源请求和非白名单静态资源，不代理业务写操作。状态文件缺失、损坏或版本不支持时，页面保留上一份有效快照并明确标记，不改写源文件。

## 页面结构

桌面页面分为三栏：

- 左侧列出请求、代码交付和尝试次数；演示模式使用 `DEMO-DOC-PR-001`、`DEMO-TASK-001`、`DEMO-CODE-PR-001` 标识合成产物。
- 中间使用 React Flow 绘制后端提供的全部真实节点，或在演示模式绘制单一完整故事。画布支持平移、控件缩放、全图适配、小地图和“专注画布”。
- 右侧展示选中节点、请求或交付的详情，包括状态说明、PR 记录、SHA、尝试记录、部署结果和回执状态。

真实模式不假设固定节点数。当前八阶段 DTO 会显示为一条蛇形主路径；其他节点数也按相同的只读规则动态排版。节点不可拖动或连线，键盘可聚焦并通过 `Enter`/空格选择。鼠标滚轮用于平移画布，右下角控件用于缩放和全图适配。面板只展示已有证据；缺失数据标为“未记录”或“未知”，人工等待标为“待人工确认”，未启动阶段标为“未执行”。

## 演示模式

页面右上角可切换到“演示模式”。进入后立即停止真实轮询，并从暂停的“文档草稿 / 验收标准”开始。唯一故事是“计数器增加翻倍功能”：新增翻倍按钮，同时保留原有步长、增加、减少与重置行为。主路径包含 14 个节点；另用 4 个分支节点展示固定检查失败回路、构建/健康失败、回执补偿和终止分支，合计 18 个节点。

演示时间线只改变本地合成画面，可播放、暂停、下一步和重置：

- 文档确认和代码确认是两个独立人工门禁；“播放”“下一步”和自动计时都会在门禁前暂停。
- 固定检查的首轮失败会保留 attempt 1；只有显式“模拟重试”才创建 attempt 2 并回到 Worker。
- 代码确认后，main 游标切换到代码合并/发布 SHA；需求文档与交付中的源 SHA 继续保留文档合并 SHA。
- 完成状态保留失败尝试、最终部署、预览切换、新 SHA 和 `DEMO-RECEIPT-001` 回执证据。
- 重置会清空确认、失败尝试和完成证据并回到暂停草稿；完成后重播同样清空旧证据，但从草稿自动播放。

播放时默认跟随当前节点；手动选择节点后保留该选择，重置恢复跟随。失败回路、版本过期和其他长分支使用独立通道绕开节点。页面顶部持续显示“演示数据”，不会请求 Merge、Retry、Deploy 或其他写接口。演示产物使用明确合成编号，不生成指向真实 GitHub 对象的链接。

切回“真实数据”后，合成选择被清除并恢复只读轮询。面板 API 断线时保留上次有效快照；控制器离线只影响运行提示，不会把历史任务自动改写为失败。

## 验证边界

`npm run build:panel` 只验证独立面板资源可以生成，`npm run typecheck` 与自动化测试验证类型、状态门禁、产物时序和合成视图契约。真实面板仍需要在本机启动服务后核对状态文件、HTTP 安全边界、控制器健康探测和浏览器交互。Vercel 或其他静态前端发布不代表本机控制器、状态读取或飞书链路已经运行。
