# 本机只读流程面板

本机面板用于观察需求请求、代码交付与八个固定阶段的只读证据，不提供重试、合并、部署或任意文件访问入口。产品行为仍以已进入 `main` 的 `docs/specs/*.md` 为准；面板展示不能替代 GitHub、固定检查、部署与人工验收记录。

## 启动

使用 Node 24，在仓库根目录执行：

```bash
npm ci
npm run panel
```

`npm run panel` 先运行 `build:panel` 生成独立的 `.orchestrator/panel-dist/`，再启动只监听 `127.0.0.1` 的 Node 服务。默认访问地址为 <http://127.0.0.1:4001>。原有计数器前端开发页和构建产物不受影响。

面板服务从显式状态路径读取快照，默认路径为当前目录下的 `.orchestrator-state.json`。可通过 CLI 指定状态文件、面板端口和控制器健康检查端口：

```bash
node orchestrator/panel.ts \
  --state /absolute/path/to/.orchestrator-state.json \
  --port 4001 \
  --control-port 4000
```

参数由面板服务严格校验，不允许监听非本机地址。面板只接受 `GET`/`HEAD`，拒绝跨源请求和非白名单静态资源，不代理业务写操作。状态文件缺失、损坏或版本不支持时，页面保留上一份有效快照并明确标记，不改写源文件。

## 页面结构

桌面页面分为三栏：

- 左侧列出当前与历史需求请求、代码交付和尝试次数；代码交付单独展示关联依据。
- 中间使用 React Flow 绘制“接收需求 → 生成文档PR → 文档人工确认 → 同步开发任务 → 编码与验证 → 代码人工确认 → 构建与部署 → 健康检查与回执”，支持缩放、平移、全图适配和小地图。
- 右侧展示选中节点、请求或交付的详情，包括状态说明、PR 链接、SHA、尝试记录、部署结果和回执状态。

画布固定为 4×2 蛇形布局。节点不可拖动或连线，键盘可聚焦并通过 `Enter`/空格选择。面板只展示已有证据；缺失数据标为“未记录”或“未知”，人工等待标为“待人工确认”，未启动阶段标为“未执行”。

## 演示模式

页面右上角可切换到“演示模式”。进入后立即停止真实轮询，并使用浏览器内合成数据展示五种场景：

- 运行中
- 待人工确认
- 失败
- 重试后成功
- 已部署

演示时间线只改变本地合成画面，可播放、暂停和重置。播放时默认跟随当前节点；手动选择节点后保留该选择，重置恢复跟随。页面顶部持续显示“演示数据”，不会请求 Merge、Retry、Deploy 或其他写接口。

切回“真实数据”后，合成选择被清除并恢复只读轮询。面板 API 断线时保留上次有效快照；控制器离线只影响运行提示，不会把历史任务自动改写为失败。

## 验证边界

`npm run build:panel` 只验证独立面板资源可以生成，`npm run typecheck` 与自动化测试验证类型和合成视图契约。真实面板仍需要在本机启动服务后核对状态文件、HTTP 安全边界、控制器健康探测和浏览器交互。Vercel 或其他静态前端发布不代表本机控制器、状态读取或飞书链路已经运行。
