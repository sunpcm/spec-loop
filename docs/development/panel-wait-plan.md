# 面板等待说明的框架任务拆解

操作者打开同一条需求，在不同时间可能分别要做两件事，一次是确认文档，另一次是决定开工。面板需要读取该次交付的事实，告诉操作者现在该做哪一件。产品行为和验收以 `REQ-PANEL-01` 为准。下文 A1 至 A8 对应这份规格“验收”中的八条，按顺序引用。[产品需求与验收](../specs/pending/panel.md)

## 这次文档如何合并与排期

1. **操作者合并文档 PR。** 这次合并确认需求。规格暂存于 `docs/specs/pending/panel.md`。当前主线只扫描 `docs/specs/` 的直接子文件，#16 的运行时也只对 `REQ-CNT-01` 核验人工开工许可。放在子目录可使这次合并产生零项受管需求变更。[主线扫描范围](../../orchestrator/git.ts) · [#16 派工方案](https://github.com/sunpcm/spec-loop/pull/16)
2. **任务 Agent 登记待排期。** 合并后按本仓与需求 ID 查重，将已确认提交、规格路径、工作项和 A1 至 A8 记到一张普通 GitHub Issue。首轮由任务 Agent 显式登记，初始状态写为“待排期”。当前控制器还不能自动登记这份暂存规格。登记过程只发布计划，保留空的开工许可，不给旧调度器设置可领取状态。
3. **先让运行中的控制器具备面板派工能力。** 工作项 1 至 3 可以合在一张框架前置任务里，列明范围、版本和验收。首轮由维护者核对该任务公布后操作者本人添加的当版标签，再安排框架实施。框架许可只覆盖该任务，面板 Issue 继续待排期。
4. **由操作者决定面板何时开工。** 新门禁上线后，在受信配置中显式登记这份已合并规格的确切路径，首轮可直接读取原文。任务 Agent 按已确认的需求块哈希复用原 Issue，发布冻结清单、版本以及本版所需的 `可开工/rN`。操作者在发布后添加该标签，调度器核实身份、版本和有效事件，领取一次并把同一份清单交给 Code Agent。若行为或验收改版，先合并新文档，旧许可失效，新版重新待排期。代码 PR 由操作者审查合并。

## 工作项与交接

| 工作项 | 现有实现与需要改动的地方 | 交付验证 |
| --- | --- | --- |
| 1. 让面板需求也受人工排期约束 | 复用 #16 的冻结计划、许可、领取和重试。把仓库、主线、需求 ID、规格路径及可写路径作为受信配置，文档对账、普通轮询、显式重试和合并前检查读取同一份绑定。首次登记依据已确认的提交和普通 Issue 编号，核对同仓、同需求、同版本后接续。已有多张候选卡时停在待核实。 | 在临时 Git 仓同时登记计数器与面板。面板初次接入只公布一个待排期任务、产生零个作业。给其中一项打标只派该项。覆盖撤标、旧标迟到、提前打标、改版、重复打标、并发轮询及重启。对应 A2、A3、A6。 |
| 2. 为面板选择允许的源码范围和验收套件 | 当前 Worker 只接收 `src/**`，浏览器门禁固定选计数器。为面板绑定 `panel/src/**`、面板构建产物和已有的 `panel` 浏览器套件，Worker 与合并构建使用同一受信配置。控制器代码由框架任务维护，独立测试作者维护验收契约、用例及版本绑定。 | 面板改动只触及允许路径。面板构建和浏览器验收能发现等待说明显示错误，报告绑定本次需求版本与候选提交。覆盖 A1 至 A8。[Worker](../../orchestrator/worker.ts) · [面板构建](../../panel/vite.config.ts) |
| 3. 向只读面板提供等待依据 | 在现有 panel view 中按所选需求、请求或任务版本汇合文档 PR、冻结任务、许可、作业、代码 PR 和回执。复用调度器已核实的结果，提供处理角色、原因、下一步、证据引用和观察时间。尚未生成作业的已发布需求也应可选。离线、资料不足与已终结分别表达。 | 用状态快照覆盖 A1 至 A7。特别验证 r1、r2 内容即使相同也按版本区分，未领取的任务可见，旧回执只进入自身历史。普通查看不轮询写接口。[现有只读视图](../../orchestrator/panel-view.ts) |
| 4. 在所选需求的详情里显示并独立验收 | 面板消费只读视图，在现有详情展示角色、原因、下一步及可用的证据链接。演示使用自己的数据。任务 Agent 将公布在 Issue 的工作项和验收引用原样交接给面板 Code Agent。 | 独立测试作者用受控的面板浏览器门禁验证 A1 至 A8。至少设置一个反例，让旧版成功回执错误地占用新版说明时测试失败。每条验收记录实际结果、提交及证据位置。[现有面板](../../panel/src/App.tsx) · [本机面板说明](local-panel.md) |

工作项 1 和 2 可分别验证。工作项 3 使用 1 提供的可信状态。工作项 4 使用 2 的执行配置及 3 的只读视图。可在 Spec Loop 本仓及临时测试仓走完这些步骤。

## 真实验收时保留什么

记录文档合并提交、待排期 Issue、冻结任务版本、操作者的打标事件、唯一作业和代码 PR。面板截图或测试结果分别对应 A1 至 A8。部署结论另外引用同一版本的健康检查和发布回执。文档确认、框架就绪、面板获准开工和交付完成各有可核对的记录。
