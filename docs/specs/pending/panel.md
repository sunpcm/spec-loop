# 流程面板

### [REQ-PANEL-01] 查看一条需求在等谁、为什么

#### 功能

- 操作者在本机面板的真实模式选中一条需求后，能在详情里直接读到谁负责下一步、当前停在这里的具体原因，以及接下来会发生什么。负责人按角色显示，例如“等你确认文档”“等调度器释放作业名额”。正在执行、已经结束和暂时无法判断各有明确说明。
- 说明只采用所选需求和所选版本的记录。有对应的 Issue、PR、验收结果或部署回执时，提供该记录的入口。要求用户打标时，显示该版 Issue 上公布的准确标签。
- 控制器离线时标明最近一次观察时间。证据不足或彼此冲突时写明缺少哪项依据。操作者可以查看历史版本和演示数据，两者都有明确标识。查看详情只读取状态。

#### 验收

- 选中一条文档 PR 已打开、尚未合并的需求时，显示“等你确认文档”、原因和该文档 PR 的链接。
- 文档已合并、控制器已记录任务待登记时，显示“等任务 Agent 发布清单”。Issue 公布 r1 且本版尚无有效开工许可时，改为“等你排期”，说明需要在该 Issue 添加 `可开工/r1`。领取前撤下标签后，刷新应再次看到排期说明。
- r1 已获准、唯一作业名额被占用时，显示“等调度器”，原因是名额被占用。名额释放后本版作业已开始时，刷新显示“Code Agent 正在执行”，人工待办为空。
- 本版代码 PR 等待合并时，显示“等你审查代码”并链接该 PR。合并后只有构建记录时，显示“等控制器完成发布”。直到本版健康检查和部署回执齐全，才显示“已部署，无需操作”并给出回执入口。
- 本版作业在浏览器验收阶段失败、记录要求人工处理且附有失败报告时，显示“等你处理验收失败”，并指出失败的验收及其报告入口。
- r2 已公布，只有 r1 有开工标签或成功回执时，选择 r2 仍显示“等你排期”和 `可开工/r2`。选择 r1 时看到标为历史的 r1 记录。切换到另一条需求时只显示新选择的依据。
- 控制器离线且有缓存时，显示“控制器离线”和上次观察时间，缓存结论标为“上次记录”。在线但所选版本的许可状态不可核实，或同版本记录互相冲突时，显示“待核实”、具体缺口和“负责人未知”。
- 连续打开、切换和刷新详情，GitHub 写入与新增作业数均为零。切换到演示模式后，等待说明带有演示标识。切回真实模式后，说明来自当前选中的真实记录。
