# 需求登记

这份文档合并后确认框架需求。按[同仓已合并的 #17 先例](../../development/panel-wait-plan.md)由现有手工交接登记本框架 Issue，并等待操作者单独添加开工许可。现有主线扫描规格目录的直属文件。#20 另支持显式绑定面板规格，这份文件由手工交接登记。框架能力交付后，已登记的业务规格合入 `main` 由任务 Agent 自动登记或复用 Issue 并冻结，不再逐项手工派工。已打开的 #19 是独立面板实施卡，本卡不改变其排期或开工许可。

### [REQ-REG-01] 维护者通过受信配置接入同仓新需求

#### 功能

- 维护者在同一仓库的受信配置中登记业务规格，并选择已有的允许写集、构建命令和独立验收套件。规格合入 `main` 后，任务 Agent 按仓库和需求 ID 自动创建或复用普通 Issue，在本 Issue 冻结版本并置为待排期。
- 框架首次实现可以修改控制器、调度或重试相关核心代码。能力可用后，维护者通过第三个临时样例验证只增加规格、受信配置和必要验收即可接入新需求，不再修改调度、重试或合并核心。该样例是接入验证，不是长期派工项或额外产品。
- 同一需求跨版本保留一个 Issue。新版在原 Issue 冻结清单并公布本版所需标签名 `可开工/rN`，由操作者添加。重复添加同一标签不产生第二次登记或领取。
- 冻结时记录仓库、需求 ID、规格路径、需求块哈希和来源提交。Worker 在送验时记录候选 tree，合并构建记录实际合并 tree，验收和发布回执据此关联同版交付。
- 规格和 Issue 中的路径或命令文本按内容处理，不会自行执行。未登记、候选含糊或请求超出受信写集时不派工。
- 同一项目的多个需求分别登记、冻结、打标和领取，互不占用版本或许可。改版保留旧记录，计数器与面板原有路径继续工作。

#### 验收

- 在真实临时 Git 仓及模拟远端中，让维护者按说明使用现成计数器组合，加入一个不同需求 ID 和不同验收的临时例子。首次框架实现可有核心改动，此后该例子的接入 diff 不再修改调度、重试或合并代码。
- 将受信业务规格合入 `main` 后，任务 Agent 产生恰好一个待排期 Issue 并发布冻结清单。待排期阶段 Worker=0，再次对账复用该 Issue，不重复建单或发布第二份当前版本。
- 同一仓库、同一套构建与验收配置下有两条不同需求 A、B。只给 A 打本版标签时，A 领取一次，B 的作业数为零。两者都获准时按既有单作业规则依次执行。
- 同一需求从 r1 更新到 r2 时，Issue 数量仍为一。r2 清单发布前旧标签不能领取，发布后重新添加 `可开工/r2` 才产生一次领取，重复添加同一标签不产生第二个登记、许可或作业。
- 可信验收套件由受信配置选择。冻结记录核对仓库、需求 ID、规格路径、需求块哈希和来源提交，Worker 送验时核对候选 tree 及候选验收，合并构建记录实际合并 tree，最终验收和回执据此关联当前需求、路径、版本和对应 tree。规格和 Issue 本身不要求携带候选。
- 错版报告不算本版，并阻止本次发布。若来源、标签和授权事件仍然有效，该报告本身不撤销许可。改版后旧标签不能派新作业，领取前撤标也不派。
- 规格中出现普通路径或命令文本时原样保留，既不执行也不因其出现而拒绝。未登记、存在多个候选或声明不一致时产生零个作业，实际越权请求不产生写集外写入或凭据访问。取得本版许可后，允许动作正常执行且只领取一次。
- 新需求首次验收失败后，在同一 Issue 显式重试，Worker 仍使用本版许可、写集和验收配置。计数器与面板保留各自既有门禁和历史记录，可独立查看。
